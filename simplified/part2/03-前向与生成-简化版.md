## 一句话核心

一个 token 从 embedding 查表 → 多层 Transformer Block（Attention + MLP）→ LM Head 得 logits → softmax/采样 → 下一个 token；这个"前向一次、生成一个"的串行循环，就是自回归生成。

## 核心概念（只留能算账的公式）

- **前向链路**：文本 → tokenizer 切分映射成 id → embedding 查表 `[B,T,d_model]` → 位置编码（RoPE，对 Q/K 旋转注入相对位置）→ N 层 Block → final norm → LM Head → logits。
- **Attention 是跨 token 通信，MLP 是单 token 变换**：Q（我在找什么）/K（我有什么）/V（实际传什么）投影 → 多头拆分 → `scores = QK^T/√d_head` → **causal mask 把未来位置设为 -∞** → softmax → 加权 V。MLP 逐位置独立非线性，不做跨位置通信。
- **残差 + Pre-Norm**：让梯度直通深层；Norm 放在子层前（现代 LLM 标配，替代 Post-Norm）。
- **LM Head = 一个线性层**：hidden `[B,T,d_model]` → vocab，输出 **logits（未归一化原始分数，可为负、不求和为 1）**；训练用所有位置算交叉熵，**推理只取最后一个位置**。
- **采样（logits → token）**：greedy = argmax；温度缩放公式
  `p_i = exp(logit_i / T) / Σ_j exp(logit_j / T)`
  ——T↓ 分布更尖锐（更确定），T→0 退化为贪心，T↑ 趋近均匀（更随机）；top-k 固定保留前 k 个再重归一化；top-p 按概率从高到低保留累计到 p 的最小集合再重归一化。
- **Prefill vs Decode**：prefill 一次并行处理完整 prompt、建立 KV Cache、产出首 token，**compute-bound（O(n²) 注意力、GPU 利用率高）**；decode 每步只处理 1 个新 token 但频繁读显存，**memory-bound**。

## 行业 Best Practice

- **现代架构默认替换**（面试必须能脱口）：MHA→**GQA/MQA**（省 KV Cache）、LayerNorm→**RMSNorm**、Post-Norm→**Pre-Norm**、正弦绝对位置→**RoPE**、标准 Attention→**FlashAttention**（IO 感知，少访存）、稠密 MLP→**MoE**（参数量大但激活算力可控）、激活 **SwiGLU**。
- **采样生产选择**：事实问答/代码/评测用 `temperature=0`（贪心，确定性）；对话/创意常用 `temperature≈0.6~0.8 + top_p≈0.9`（各框架默认值不同，需按部署版本核对）；调低温度/收紧 top-p 可降幻觉风险但损失多样性。greedy 实现上直接 argmax，不需要真算 softmax（顺序不变）。
- **Failure mode**：把 logits 当概率直接比较；漏 causal mask → 未来信息泄漏（推理里就是"作弊"）；用绝对位置编码套长上下文外推场景；推理时对全位置做词表投影浪费算力。

## 面试考点

1. **Q：logits 和概率分布有什么区别？为什么 greedy 不用真算 softmax？**
   A：logits 未归一化、可为负、不求和为 1；softmax 后才是非负且和为 1 的概率。softmax 是单调变换、不改变大小顺序，所以 greedy 直接 argmax(logits) 结果相同，省一次归一化。
   追问：什么时候必须算 softmax？→ 随机采样（temperature/top-k/top-p）需要真实概率分布。
   陷阱答案：说"logits 就是概率"。

2. **Q：为什么 prefill 是 compute-bound、decode 是 memory-bound？**
   A：prefill 对整段 prompt 做并行 attention，O(n²) 算力密集，受 FLOPS 限制；decode 每步只算 1 个 token，算力小但要读整段 KV Cache 和权重，受显存带宽限制。
   追问：各自优化方向？→ prefill 靠算力/并行，decode 靠压 KV 尺寸（GQA/量化）和带宽。
   陷阱答案：说"decode 也靠堆算力"——算力利用率低，堆算力几乎不降 TPOT。

3. **Q：causal mask 作用？去掉会怎样？**
   A：把第 t 个位置之后的注意力分数设为 -∞，保证只能看 1..t，不偷看未来。去掉后，训练/推理时当前位置会"看到答案"，生成质量崩坏、且无法自回归（相当于作弊）。
   追问：为什么训练也要 mask？→ 否则训练目标（预测下一个 token）会直接泄漏。
   陷阱答案：说 causal mask 是为了省算力——它是正确性约束，不是优化。

4. **Q：GQA 为什么省显存？**
   A：MHA 的 K/V 头数 = Q 头数，KV Cache 大；GQA 让多个 Q 头共享一组 K/V（MQA 全共享、GQA 折中），KV Cache 显存与 K/V 头数成正比，共享后成倍下降，代价是表达能力略降。
   追问：MLA 呢？→ 进一步低秩压缩 KV，比 GQA 更省（DeepSeek 系常用）。
   陷阱答案：把"头数"当唯一因素——要区分 Q 头数和 K/V 头数（共享组数）。

5. **Q：temperature / top-k / top-p 三者区别和组合？**
   A：temperature 在 softmax 前缩放 logits 改分布尖锐度；top-k/top-p 在 softmax 后截断候选再重归一化。通常先 temperature 后 top-p（或 top-k）组合使用：温度控整体随机性，top-p 截长尾防离谱 token。
   追问：top-k 和 top-p 哪个更常用？→ 现代常用 top-p（候选数随分布自适应），top-k 的固定 k 对尖峰/平坦分布都不理想。
   陷阱答案：说 temperature 直接改 token 概率而不是先改 logits。

### 代码在干嘛（不抄代码）

- `models/qwen3.py` `Qwen3Model.forward`：embed → N 层 DecoderLayer → final norm。
- `Qwen3DecoderLayer.forward`：`input_norm → attn → post_attn_norm → mlp`，**残差加法被融合进 `RMSNormFused`**（首次调用存 residual，后续调用先加再归一化），所以看不到显式 `x + attn(x)`。
- `RopeAttn`：`qkv_proj` 合并三个投影 → attention → `o_proj`；Q/K 各头末维做 RMSNorm 后按位置应用 RoPE，V 不旋转。
- `GatedMLP`：`gate_up_proj → silu(gate)*up → down_proj`（SwiGLU）。
- `ParallelLMHead.forward`：prefill 时 `get_last_indices` 只取每条请求最后位置的隐藏态再做词表投影（省去全位置投影）。
- `generate`（教学简化）：`forward_all(tokens)[0,-1] → argmax → append → 直到 max/eos`，每轮重算整个前缀（引出第 4 章 KV Cache）。
- **改错会出什么问题**：漏 causal mask → 未来泄漏；把 logits 当概率直接抽样 → 分布错误；LM Head 对全位置投影 → 白算；去掉残差 → 深层训练/推理退化。
